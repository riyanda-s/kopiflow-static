# Customer onboarding

## Confirm scope and ownership

- Package, exact page scope, menu count, language, revision rounds, timeline and payment milestones.
- Customer name and authorized approver; repository, hosting and domain ownership.
- One repository and hosting project for this shop. Separate work for another shop or brand.
- Hosting is static; availability changes require edits/rebuilds. No POS, automatic receipt, live inventory, payments or order dashboard.

## Collect approved content

| Needed | Verification |
| --- | --- |
| Shop name, tagline, logo, colors | Client owns or licenses the assets; appropriate logo formats supplied. |
| Real address and Maps URL | Owner verifies the exact storefront and pin. |
| Hours and holidays | Owner approves wording and expected update process. |
| WhatsApp number | Owner confirms international number, recipient and response workflow. |
| Instagram URL | Correct active profile, owned by client. |
| Story and differentiators | No fabricated credentials, awards, sourcing, certifications or testimonials. |
| Products and photographs | IDs, categories, descriptions, base prices, size/temperature/sugar choices, add-ons and stock. |
| Promotions | Validity dates, exclusions and actual approved offer. |
| Domain | Desired hostname, registration owner, DNS access through an authorized method. |

Never request passwords in repository files or chat logs. Use platform invitations/roles for access. Client photographs are preferable to stock serving suggestions. Confirm allergens and ordering expectations directly with the owner; avoid collecting medical data in the website.

## Build and approval

1. Clone to a separate customer repository. Follow [CONFIGURATION.md](CONFIGURATION.md).
2. Replace all fictional wording and placeholders in configuration, metadata and content.
3. Validate menu prices and all option surcharges with an owner-approved price sheet.
4. Show a local or explicitly authorized preview. Collect one consolidated revision list per round.
5. Run functional, responsive and accessibility QA. Demonstrate that WhatsApp prepares a message and retains the bag; the customer must send and await confirmation.
6. Obtain approval of the concrete final content and deployment destination before publishing.
7. Configure the final domain, verify QR, and complete handover. A sale does not automatically authorize buying domains or creating paid services.

## Acceptance sign-off

Record date, approver, source commit, production domain, package, actual QA results, known exceptions, maintenance start/end and who handles future prices/promotions. Keep client records outside the public repository.
